# Daily Workflow Optimization Tool

> Every night, [Codex CLI](https://github.com/openai/codex) autonomously writes a small workflow utility tool based on a task queue.

## How It Works

1. A cron job runs `run_nightly.sh` at 02:00 each night
2. `orchestrator.py` picks the next `pending` task from `tasks.yaml`
3. It calls `codex_runner.sh` with the task prompt
4. The generated tool is saved to `tools/<timestamp>_<slug>/`
5. The log and this README are updated automatically

## Quick Start

```bash
# 1. Install Python dependency
pip install pyyaml

# 2. Configure your API key
cp .env.example .env
$EDITOR .env          # fill in OPENAI_API_KEY

# 3. Install the nightly cron job (runs at 02:00 by default)
bash scripts/install.sh

# 4. Test it manually first
python3 orchestrator.py --dry-run   # preview only, nothing written
python3 orchestrator.py             # actually runs codex and saves output
```

## Adding New Tasks

Edit `tasks.yaml` and append a new entry:

```yaml
  - id: "006"
    status: "pending"
    slug: "my-new-tool"
    prompt: |
      Write a bash script that does X, Y, and Z.
      Output only the script contents, no explanation.
```

## File Structure

```
OMG/
├── run_nightly.sh        # Cron entry point
├── orchestrator.py       # Core logic
├── codex_runner.sh       # Codex CLI wrapper (swap out AI CLI here)
├── tasks.yaml            # Task queue
├── config.yaml           # User configuration
├── scripts/
│   └── install.sh        # Cron / systemd setup
├── tools/                # Generated tools (created at runtime)
│   └── YYYY-MM-DD_HH-MM-SS_<slug>/
│       ├── prompt.txt
│       ├── output.sh (or .py)
│       └── meta.json
├── logs/
│   └── run.log           # Append-only JSON log
├── .env.example          # API key template
└── .gitignore
```

## Configuration

Edit `config.yaml` to change schedule time, model, timeouts, and paths.

```yaml
schedule:
  hour: 2      # run at this hour (24h)
  minute: 0

codex:
  command: "codex"         # binary name on your PATH
  model: "o4-mini"
  timeout_seconds: 300
```
